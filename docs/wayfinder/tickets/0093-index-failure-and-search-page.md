## Question

浮层按 ADR-0013 决策 6 已有可见错误态（「索引加载失败」+ 引导去 search 页）与空态，而 search 页的 fastsearch 仍保留 ADR-0010 记为已知限制的 XHR / `JSON.parse` 静默失效。v2 要不要处理这条落差：

1. **语义统一与否**：两个加载面的失败语义要不要一致？「一致」的最小定义是什么（都可见？都引导？还是仅错误文案同源）？
2. **重评路径**：若统一需要改 `fastsearch.js`，是否等于重开 ADR-0010 决策 5 的「不重写」结论与 ADR-0013 决策 1 的「fastsearch 一字不改」？重开要满足哪些触发条件、走什么流程（ADR-0013  decision 1 的重评先例），还是本图只做「决策」不碰文件？
3. **负向边界**：若不统一，这个不对称要写在哪个契约定义处、给 ADR-0010 / 0013 加什么指针行，才能避免后来者把它当漏实现补上？
4. **浮层自身策略**：懒加载索引的缓存、失败后重试、以及 `indexUrl` 缺失 / 非字符串时的降级（ADR-0011 的 params 降级先例）是否属 v2 的决策面？错误态文案是否需要进 i18n（坑点 15：文件名必须与语言键一致）。

边界（不开票）：不重写 fastsearch（Out of scope）、不改投影六字段；具体断言归属归「可测试性的判据与测试缝归属」。事实以「搜索浮层 v2 现状事实底座（盘点）」为准。

## Resolution

2026-11-15 · HITL grilling（项目负责人实时对话定案，含两轮补问）。

**主决策 = 不统一，把两面容错不对称固化为有意设计的负向边界。**

- 给 **ADR-0010 / ADR-0013** 各加一行指针：写明「浮层有可见错误态、search 页仍静默失效」是有意的不对称，**勿当漏实现补上**；附重开触发条件（真被 XHR 静默失败咬到 / 结果可读性成为真实需求）。
- fastsearch 一字不改（ADR-0013 决策 1）；不重开 ADR-0010 决策 5；不回头修订 0090 分层判据。
- 未选「统一到都有可见错误态」（触发重评且与 0090 冲突）与「整体外推出本图」（触发条件确已出现：浮层错误态正引导用户去一个同样失效的页面）。

**补问 2 · 浮层不自动重试、失败不写缓存**：失败即显示错误态；缓存只存成功结果，关闭再打开自然重新拉取（用户主动行为，不写进契约）；不加退避 / 次数上限 / 新 docstring 条款 / 新断言。MFO-8、MFO-14 / 14b / 14c 不动。

**补问 3 · 改文案 + 继续硬编码中文**：删掉「或前往搜索页」的误导（改为「索引加载失败，请稍后重试。」），仍写在主题层 `themes/maplemod/layouts/partials/search-overlay.html`，**不进 i18n**（单语言站、骨架已有硬编码先例、不扩契约面）；配一条产物弱断言守文案子串。

**indexUrl 缺失**沿用 `initSearchOverlay` 返回 `null` + MFO-2 降级，不变。
