## Question

产品状态推导（已上架 / 即将上架 / 免费 / 可下载产品，含占位例外）应驻留在哪？候选形态：

- (a) 单一 template partial 单源 + 构建产物级测试；
- (b) 构建期派生脚本（Python / Node）读 `products.yaml` 产出派生数据 + 单测；
- (c) 混合：partial 单源 + 独立校验脚本。

决策依据：工单 0001 的事实、ADR-0001 固定构建命令约束、本地 dev 与 CI 双流程成本、「接口即测试面」原则。

本工单同时划定模块职责边界：模块是只拥有状态判定，还是连同 CTA 文案 / 价格展示映射一起拥有。

## 背景约束（来自工单 0001 决议，2026-10-15）

- Hugo 无模板单测机制，测试只能「build 后对产物断言」—— seam 形状直接决定测试能否单点覆盖。
- return 型 partial 在 0.164 限「单变量 + 根级单条 return」；0.166 起才支持条件多 return。
- **版本 skew 已核实**：本机 hugo 0.167.0，CI 锁定 0.164.0 —— 同一写法两端行为可能分叉，深化方案必须按 0.164 语义编写。
- data/ 纯静态，无构建期计算；构建期派生只能靠 partial/store（构建内）或预构建脚本（构建外）。

## Resolution

2026-10-15 · grilling（用户为决策者），四维全部落定：

1. **seam 位置**：单一 return 型 partial（模板内单源，`product-index.html` 与 `index.html` 共用）。「规则可单测」经用户拍板**不设为硬要求**——接受 Hugo 生态内测试只能穿过渲染产物。排除预构建脚本：其「漏跑一步 = 陈旧派生数据静默渲染」会制造新的静默腐化源，与目的地「可测试」自相矛盾。ADR-0001 构建命令与 `hugo server -D` 零变更。
2. **模块形状**：形状 B——模块拥有状态判定**+ 控件/文案语义**（可点/禁用、购买/免费获取/即将上架、`data-price` 值）。理由：「即将上架」等文案是 CONTEXT.md 状态术语的用户面命名，留在模板等于让表示层掌握领域规则；删除测试下复杂度整体回迁，深度最大。
3. **seam 后面的规则全集**（5 条，用户确认无遗漏）：① 已上架判定（buy_url 存在且非占位，占位表示见 0003）② 免费判定（price 显式 0，缺省处置见 0003）③ 控件语义（已上架+免费→可点「免费获取」；已上架+付费→可点「购买」；未上架→禁用「即将上架」，与价格无关）④ 筛选属性 data-price 派生 ⑤ 可下载计数 = 已上架条数。**搜索索引投影不外扩**（index.json 不消费状态，拉入只会稀释深度）。
4. **存活测试集**：两条产物断言即 100% 覆盖——`products.html` 逐条控件态+data-price（覆盖①②③④，当前两条 price=0 占位条目正是「未上架+免费→仍即将上架」的现成 fixture）+ `index.html` 数据条计数（覆盖⑤，即当前 5-vs-0 失实格）。规则单测入土；数据契约检查归 0005 裁断。

**附带事实**（质询中查出，非本工单决策）：`layouts/_default/index.json:34` 搜索 tag 硬编码 `"资源"`，违反 CONTEXT.md 已批准术语（canonical「产品」）——修正留执行期，一个字，执行既有决策不新开工单。

**下游影响**：0005 仍 blocked（还等 0003）；0006 解除阻塞进入 frontier。雾区「构建集成方式」随脚本方案排除而蒸发。
