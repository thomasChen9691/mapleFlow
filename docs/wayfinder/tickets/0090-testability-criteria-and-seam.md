## Question

Destination 里的「**可测试**」以什么为判据，v2 的测试缝落在哪——本图第一张决策票。要决策的面：

1. **判据本身**：「可测试」是指「每个契约条款都有可定位地红的断言」，还是「关键行为面有常驻行为测试即可」？给出可证伪的验收句（例如某条款被破坏时哪一层会红）。
2. **所有权分层是否延续**：ADR-0011 决策 4 的「新代码常驻行为测试、legacy 引擎弱断言 + 一次性验证」在 v2 是否继续适用？浮层引擎是「我们新写的代码」，那 fastsearch 侧与主题骨架分别算哪一类？
3. **测试缝的形状**：新契约与测试是否必须 TDD 同时出生（ADR-0013 决策 9 先例）；是否需要新增 fixture 构建 / 第四套 config（ADR-0011 决策 4 与 ADR-0013 决策 9 都写「无第四套 config」）；行为断言挂 `assert_search.mjs` 还是另立套件。
4. **parity 门的边界**：ADR-0016 的 RGR-14（JS 写的状态 token 必须有 CSS 消费）是否要扩到浮层 v2 新增的 DOM 状态；若扩，与 ADR-0016 决策 17「`mf-*` 视觉类不进反向」如何共存。
5. **一次性验证的地位**：ADR-0011 记在案的一次性 jsdom 验证（驱真实构件 + 真实索引跑完整 fuse 链路）在 v2 是升级为常驻断言，还是继续保留为「已知限制 + 记录在案」？

边界（不开票）：具体做不做方向键 / 高亮归「方向键导航与命中高亮的取舍」；a11y 与移动端形态归「移动端与小屏的 a11y 契约」；施工排期归收口票。事实以「搜索浮层 v2 现状事实底座（盘点）」为准，不重新推导。

## Resolution

2026-11-15 · HITL grilling（项目负责人实时对话定案；五轴质询：约束 / 依赖 / 深化后形状 / seam / 测试存活）。

**决策 = 分层判据**（采纳推荐）。「可测试」按所有权分层验收，不是一刀切：

1. **浮层引擎**（站点层、我们新写）：`mf-search-overlay-engine.js` 头 docstring 的每一条契约条款都要有**可定位地红**的断言；新增条款与新断言同时出生。
2. **主题层 DOM 骨架**：只走产物断言（全站加载面 / indexUrl 子路径 / 默认 hidden / role / no-js）。
3. **legacy fastsearch**：维持 ADR-0011 决策 4 的弱断言 + 记录在案的一次性验证，不重写、不为 legacy 内部机制给 CI 征税。

即把「所有权分层」从两类（入口引擎 / fastsearch）扩到三类（引擎 / 骨架 / fastsearch）。**不新增第四套 config**；parity 边界维持 ADR-0016 决策 17 与 0086 决议（`aria-*` / `inert` / `hidden` 不进反向，只守 fuse 四元组与 CSS 状态 token）。**一次性验证地位不变**：继续「已知限制 + 记录在案」，不升级为常驻断言。

**分支决议（补问 1）**：`isOpen` 文档-实现不一致按「**删文档对齐实现 + 补返回形状断言**」消解——docstring 与 `assert_search.mjs` 测试头都改为 `{ open, close }`，另加一条 jsdom 断言守返回键集合；不补实现、不新增公开 API（`isOpen` 零消费方，ADR-0015 决策 6 投机泛化判据）。

**验收句**：破坏任一引擎 docstring 条款或返回形状，对应行为 / 产物断言必须可定位地红；`isOpen` 不得再以任何形式出现在契约文本里。

边界：具体断言条数与落点属收口批施工；fastsearch 一字不改（ADR-0013 决策 1）。未选「统一条款级」（会推动 fastsearch 重写、触发 ADR-0010 决策 5 重评）与「最小判据」（会留返回形状零断言的洞）。
