## Question

harness 收敛的第一步是划定边界：四个套件里的每一类现存重复，判为**基建**（进 harness，只留一份）还是**契约**（按三层文档契约保持独立字面量）。判据必须可复用——未来的新重复也要能按它归类，否则 harness 的边界会随每次迁移漂移。

要决策的面：

1. **判据本身**：候选标准——「改一处是否必须同改」（基建：不同改即行为分叉）／「是否是某契约的定义处或期望值」（契约：独立性是承重设计，ADR-0007 三层模式）。两条候选是否充分、以哪条为主、冲突时谁赢。
2. **灰色地带逐类裁定**（每类给出判 + 理由）：
   - 坏用例期望子串 `BAD_CASE_EXPECT` 在两个 Python 套件间的同型镜像（:176-189 与 :77-84，注释自证「有意同型」）——判基建还是契约？
   - fuse 配置的两处执法：assert_site_contracts.py 的 regex 解析两源文件（约 :1493-1505）vs assert_search.mjs 的字面量（约 :294-297）——比较逻辑是基建、期望值是契约，能否这样切？
   - 站点套件对 SOP fixture 数据的借用（assert_empty_state 约 :1307-1309 拷贝 `tests/fixtures/data/sop.yaml`，头部注释自证为陷阱）——共享 fixture 数据判基建还是契约？
   - sop_golden 的 golden 文件与 capture/assert 分工——内容 fixture 工具是否在 harness 边界内（初步落点见 golden 关系工单，本票只判类别）。
3. **判定的产物形态**：一份「重复分类清单」（类别 → 判定 → 判例理由），作为后续所有工单的输入；清单落点（工单 Resolution 即唯一存放处，地图只留 gist）。

边界（不开票）：具体模块形态与落点归形态工单；契约语义的修改（如改某个 errorf 前缀）不在任何工单范围——那是新目的地。字面量独立的既定部分（各套件期望值、变异检验纪律）不开重开票。

事实前提：架构评审候选①（报告在 OS 临时目录，epoch 性）。行号锚点——Report ≡ assert_site_contracts.py:376-386 / assert_sop_pipeline.py:206-216；run/build ≡ :367-373 / :117-128；check() ≡ assert_reveal.mjs:31-39 / assert_search.mjs:39-47；TOML 手写六处 ≡ fixture_config :218-236、assert_featured_passthrough :397-405、assert_bad_cases :1332-1335、assert_bad_caller_limit :1361-1363、assert_bad_caller_direct :1387-1388、assert_empty_state :1310-1311；jsdom 内联五处 ≡ assert_search.mjs :51/:93/:128/:191/:220。

## Resolution

2026-10-25 · grilling（HITL，项目负责人八问定案）：

**判据（Q1）**：**所有权测试**——一份重复判基建，当且仅当它在全部套件中应该只有一个所有者（消费方只调用不编辑；某套件要不同行为时，正确解法是参数 / 档位，不是拷贝）；判契约，当每一份各有其主（为各自的契约理由独立变动）。**平分 tiebreak 判契约（保持独立）**：合并「意义」制造隐形跨套件耦合——改 A 套件的契约会静默改变 B 套件的断言，代价无界且无报警；重复「机制」的代价有界且看得见。票面候选的「必须同改」标准**废除**：它描述的是症状不是判据（契约字面量漂移同样无人报警，分不开两类）。

**分类清单（Q2–Q6，判 + 理由）**：

1. **BAD_CASE_EXPECT 两份同型 dict + 各自消费循环 → 契约，留各套件**（Q2）。表是各套件对其**被测模块**的期望字面量（站点侧钉「产品状态：」前缀、SOP 侧钉「SOP 发布管线：」前缀，用例集不同），各有其主。循环虽同型，但两侧有真实差异（站点侧 `:1337` 带默认回落「产品状态」、SOP 侧 `:335-337` 多一条表完整性自检、fixture 布局与配置写入不同）——合并是搬家加参数化，不是集中。**重开触发**：出现第三个坏用例套件时，回迁移工单重估循环是否进 harness。
2. **fuse「双执法」→ 都不是 harness 基建，维持现状**（Q3）。事实核查改写票面前设：Python 侧（`assert_site_contracts.py:1491-1505`）是**源文件对源文件比对**（`_fuse_cfg(fast_txt) == _fuse_cfg(overlay_txt)`，零硬编码期望值）；mjs 侧（assert_search.mjs MFO-10）钉**硬编码字面量**。二者不是同一执法的两份拷贝，而是覆盖不同漂移方向的互补 pair（双引擎同改 → 仅 mjs 红；单边漂移 → 仅 Python 红）。ADR-0013 决策 5 的设计本体，不动。
3. **tests/fixtures/data/sop.yaml 镜像 → 基建侧，留原地不加牙**（Q4）。事实核查**消灭了「跨套件借用」前提**：该目录是站点套件**自持的 dataDir**（products.yaml + 镜像，`hugo.test.toml` 与 `:1362` / `:1388` 三处构建共用），SOP 套件的 fixture 在 `draft/`、`featured/`、`bad/sop-*` 且各自带注册表。镜像单一所有者、零断言消费者（头注释自证）、缺条目时 ref 解析**大声失败**——是机制材料不是契约。harness 是代码模块，不收数据文件。拒绝「镜像覆盖生产 slug」断言：advisory 同步够用，加牙是站点套件与生产数据的新耦合。
4. **tests/fixtures/bad/ 共享坏用例 → 契约，拆子根**（Q5；本票第五块灰色地带，0065 边界注记移交、票面漏列）。15 个用例（9 产品侧 + 6 SOP 侧，今日无混装）各有其主。所有权机制 = **`bad/products/` + `bad/sop/` 子根 + 每根一条卫生断言**（本根内每个用例须含本模块标记，错放即大声失败）——与本地图 tmp 分根同款「所有权从约定变为结构」，且文件系统自解释，AI 导航不需要先学标记约定。拒绝：标记分治 + 无主守卫（保留按内容判所有权的约定，未来贡献者须先知规则）；共享库统管（与判据直接冲突）。
5. **sop-golden → 契约**（Q6）。golden 文件是 SOP 正文变换的期望输出样本，归 SOP 套件（唯一消费方）。工具链（`sop_golden.py` + capture）与 harness 的结构关系归 **0070**，本票不越位。拒绝：sop_golden 进 harness（harness 开始懂内容语义，机制 / 意义边界从这一票起浑浊）；golden 迁进 SOP 专属根（单一消费方且目录名自解释，迁移增益近零，纯为哲学一致）。

**seam 禁止项与测试存活复查（Q7，全部确认）**：

- **seam 之后只有机制、零契约知识**：harness 对消费方承诺跑构建 / 收报告 / 写 fixture 配置 / 装 DOM 页面 / 管 tmp 根；禁止知道任何模块的词表，禁止存任何期望值或 fixture 数据。四套件的契约字面量原样留在各套件，独立性不变。
- **测试存活**：现存断言**全存活**——本票不合任何行为，无断言删除、无断言改写；唯一代码级变动是 bad/ 拆子根时两套件 glob 路径同改；净新增断言只有一类（本根卫生）。
- **三条下游约束**（对 0062 / 0066 / 0069 有约束力）：① harness 禁止存契约字面量；② bad/ 拆子根与卫生断言**同批**落地（进 0069 迁移范围）；③ 迁移期测试总数不减、每条仍有牙（变异检验纪律，ADR-0009）。

**产物形态（Q8）**：判定清单与判据只存于本 Resolution（tracker 纪律：决策只存在于工单）。**给 0067 的建议**：判据可复用（未来的新重复会踩到），值得在 AGENTS.md 坑点区或 harness docstring 耐久化——形态归 0067 裁。

**对地图雾区的了结**：雾区第一条「跨套件契约执法点的归属」随本票消解——BAD_CASE_EXPECT 判契约（各套件独立）、fuse pair 判互补（原样），均无 harness 可收部分。
