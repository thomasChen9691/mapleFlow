## Question

首页「精选文章」区块**选谁、选几条、不够怎么办、与网格重复怎么办**。事实底座：现状是 `first 3 ($pages.ByDate.Reverse)`（最新 3 篇），且与同页「最近更新」网格同源，前 3 篇必然重复（research/0035 §2）。

待决：

1. **条数**：固定 3（与产品区 `limit 3` 对齐、视觉上两栏等高），还是可配？若可配，配置载体是 `hugo.toml` 参数（受 AGENTS 参数纪律约束：必须有读取点）还是调用点字面量。
2. **featured 不足 3 篇**：显示全部 featured（少于 3 条，版面留白）？补足最新文章（混合语义，读者无法分辨）？还是**不足即整块不渲染**（空态）？0 篇时是否沿用产品侧「暂无资源」式空态文案，还是整段隐藏。
3. **与「最近更新」网格的去重**：精选 3 篇是否从网格集合中剔除？剔除后分页总数减少，是否会出现「精选占满首页导致网格为空」的边界；不剔除则同页重复展示（现状如此，但那时它叫「最新」，重复尚可解释；改名真精选后重复会变成明显缺陷）。
4. **精选内部排序**：日期倒序（简单、可预期）？还是手工序——产品侧用 yaml 数据序天然有手工序，文章侧 front matter 无顺序载体，若需手工序要引入 `weight` 或注册表式清单（成本陡增，需权衡）。
5. **区块文案与入口**：标题保持「精选文章」还是改（现状名不副实已坐实，改真精选后名实相符）；「全部文章 →」入口保留。

约束：视觉/CSS 调值不在本题（out of scope）；reveal 协议的 `reveal` class 沿用现有约定，不新造交互。

## Resolution

2026-10-21 · grilling（HITL，用户为决策者；四问全决）：

1. **去重 = 剔除**：精选 3 篇从「最近更新」网格集合中排除，网格只显示未入选文章；剔除后集合为空则整块不渲染。理由：现状同页重复是真实缺陷（`layouts/index.html:11` 与 `:122` 同源），精选越准重复越刺眼。代价已接受：分页总数随 featured 数量变动，需处理「剔除后为空」的边界。
2. **不足与空态 = 按实显示，0 篇隐藏**：1 篇就 1 行、2 篇就 2 行（`ol.mf-rows` 天然适应行数）；0 篇时整块不渲染，**不写空态文案**（首页还有其他内容，空态文案是噪声；产品侧的「暂无资源」先例不照搬——产品页是专页，空态有信息价值）。
3. **排序 = 日期倒序**：精选集内 `ByDate.Reverse`，零新字段、零歧义。明确放弃手工序（不引入 `weight`），理由是 3 条规模的收益不抵第二个字段的组合语义成本。
4. **条数 = 固定 3**：调用点字面量，与产品区 `limit 3` 对齐（两栏等高）；**不新增 `hugo.toml` 参数**（AGENTS 参数纪律：无读取点即死配置，且当前无「两栏不等高」的真实需求）。
5. **文案**：标题保持「精选文章」（改真精选后名实相符，不需要新文案）；「全部文章 →」入口保留；区块仍只在第 1 页渲染（现状保持）。

**下游影响**：0038 的 seam 必须同时产出「精选」与「其余」两片（剔除是补集需求）；0039 的「两片互斥无遗漏」断言是本题第 1 条唯一的牙口。
